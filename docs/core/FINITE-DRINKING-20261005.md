# Finite water drinking

An explicit fresh `nativeCampDrinkFactory()` installs `drink/1` on its own
physical base/rules reader. Existing factories, the global item registry and
ENGINE_RULES_VERSION remain unchanged. Old history/snapshots refuse this binding,
and the new factory does not reinterpret or upgrade existing worlds. It exposes
the actual registered `mars:drink_water` description to the compiler/control
plane, with actor implied by the actor's own program. No new steering category,
timetable, routine, need or economic rule is introduced.

The actor must have ordinary admitted humanoid hands/mouth, hold exactly one
supported bowl containing finite water, and be seated or still-standing with the
other hand free. Climbing, construction grip, water/boat/vehicle/sleep support,
walking, wrong anatomy/liquid, missing ownership and invalid quantities refuse.
One to eight sips can be requested. Each raises the actual hand/container to the
body model's mouth, pauses there, deducts exactly1/8 of the bowl, and lowers it.
Consumption happens only at the sip boundary; a failed/preempted action cannot
invent another sip, refund consumed water or reset the resource.

Cancellation lowers the hand through a finite supported cleanup before releasing
its claims. Repeated cancellation does not restart that cleanup. Cancellation
before the sip consumes nothing; after it preserves the consumed fraction.
The execution is serializable pure state and restores every next native tick.
Current hand points, container pose, activity/baseActivity and quantity enter the
ordinary take; no viewer/model is needed to replay them.

Seated drinking composes with an existing native occupied seat. It adds no root
motion writer. The optional static-clearance checker recognizes this overlay
only when the exact live sit/take_slot actor and seat claims, occupied phase,
level, position and yaw match the actual slot. A forged drink/baseActivity label
alone cannot bypass collision checks. The default invariant retains its old
behavior; the specialized predicate is installed only in this fresh profile.
This first profile does not qualify walking/swimming drinking, other vessels or
body families, multiple occupied hands or full general channel composition.

The actual owned fixture invites a synthetic human owner, admits one Soul, mints
an ordinary drinking card and accepts the owner's structured legacy agenda.
Selected fixture decision/native execution take the finite water bowl, complete
two sips, return it to its original table slot and leave fraction.75. Mid-drink
snapshot and final model-free genesis reproduce full engine/kernel hashes.
Native completed events and original take/capture windows are retained. A separate
native case proves actual supported seat + drink coexistence, safe cancellation
and exact per-tick resume; negative cases check refusals without state mutation.
No thirst/hunger benefit or ordinary-language/autonomous choice is invented.

The first admission check assumed small items had kind `item`; native bowls are
components with item capability, so it now uses the actual `isItem` descriptor.
The first public sample search selected a take whose base name contained drink
rather than a frame with drinking activity; it now examines original samples.
Seated composition exposed a genuine static-clearance invariant gap; the bounded
claim/slot predicate fixes it without blanket exemption. A nonfinite test quantity
cannot be hashed by design; direct structured equality preserves that refusal
check. All failed receipts stay in the team audit.

Focused owned/native checks and strict scoped types passed. Living behavior and
49 original social/stow cases passed separately. Public input contains selected
original take/capture pairs and actual hand/drink samples, no private owner/request
data. Source/proof pins and exact execution receipts are in the handoff audit.
World loaded-rig/gesture depiction, current Eden/Mars installation, AI choice,
other anatomy/liquids and broader composition remain separate work. No paid call,
default/candidate/main/push/deploy change or held visual/audio retry is made.
