# Reconsidering a blocked retained direction

An understood ordinary direction previously served the native chooser only on
its first publication wake. After a recorded block, the purpose stayed in
private context but later choices lost its explicit serving association.

The isolated `Brain` service switch `intentV2Retries:true` now permits
reconsideration from durable facts. It requires `intentV2Choices:true`; both
production bootstrap and the existing test defaults remain unchanged. This is
not an environment setting, client command, new mandate category or routine.

Eligibility is deliberately grounded:

- The latest owner-will change must be this current owner's active publication.
  A newer optional instruction, withdrawal or edit does not resurrect old work.
- Its interpreted direction is ordinary-now and single-step. Standing, group
  and multi-step progress adapters remain unfinished, with their context retained.
- Its latest matching attempt must be genuinely blocked. A completed,
  interrupted, accepted or started attempt is not retried. Understanding alone
  does not establish a block.
- The existing 1200 world-tick failed-option cooldown must have elapsed. This
  remains a backoff before reconsideration, not an appointment or forced action.
- Legacy active rules and unfinished agendas retain priority. The normal card
  guard, avoidance, feasibility, safe admission, writer-time ownership/lifecycle
  and version fences still apply. Evaluation may find no supported play.

The selector reads the private folded history. It adds no retry queue,
checkpoint state or model call. Timer/activity-failed/activity-ended evaluation
can plan against the eligible revision without replacing the legacy agenda.
Each actual retry receives a new logged decision, admission and attempt identity
bound to the same purpose version. Broader purpose fulfilment remains a separate,
unsupported producer; no resolve event or inferred success is introduced.

Validation distinguishes repeatable behavior from variable crowds:

1. An actual owner HTTP request and synthetic compiler publish the correct
   campfire direction. A trusted test proposal intentionally binds an absent
   native target; the real engine rejects it and records a blocked admission.
   Explicitly driven evaluation finds no retry before cooldown, then admits a
   valid campfire program. Actual controller start, arrival and completion follow
   by tick 1836. No third serving attempt is offered after completion. The broader
   purpose remains active. Engine, kernel and private history agree after saved
   snapshot and model-free genesis reconstruction. This is not a crowd-route
   failure or automatic-dispatch proof. A separate native case proves default off.
2. The existing actual 24-Soul / six invited local-owner WAL fixture opts in for
   4800 ticks. No body relocation, invented outcome or injected crowd failure is
   used. Every observed retry follows a real blocked attempt, a distinct actual
   admission after cooldown and the same purpose version. Final run: four Souls
   retried; latest phases were seven completed, five blocked, one accepted, three
   started and eight without an attempt. Complete private pages, foreign-owner
   denial, public-marker exclusion, fault-free native ticks, WAL reopen/saved
   snapshot and genesis hashes agree. These counts are not an improvement score.
3. Pure validated-history tests cover cooldown, JSON reconstruction, current
   owner, newer optional work/edit/withdraw, newer attempts and multi-step/no-block
   exclusions. Existing native ordinary response, delayed interpretation,
   withdrawal, legacy priority and target-scope checks remain green.

Affected combined run passed 25 checks. After test-only additions of kernel
recovery and default-off evidence, final native/pure run passed six checks.
Server TypeScript gate is recorded with the handoff. Paid spend is zero.

Retained failures: the first pure withdrawal fixture omitted required request
and source fields (four PASS / one FAIL). A later randomly identified population
produced no terminal blocks, invalidating a test that required at least one crowd
retry (18 PASS / one FAIL). That trace has seven completed, nine started and eight
no-attempt outcomes. The test now checks actual retry associations when present;
the separate repeatable native rejection proves the behavior occurs. Earlier
positive population traces and both failures remain in the execution record.
