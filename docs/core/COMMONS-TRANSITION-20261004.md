# An existing Greenfield world can receive the dry commons

This opt-in reader and internal checkpoint install the previously reviewed dry
commons into an existing world. Genesis remains Greenfield. No world definition,
REST/MCP permission, default factory or deployed setting is activated.

`marsCommonsTransitionFactory()` accepts exactly the old native rules and their
`+commons/1` successor. `WorldHost.adoptCommons()` records a strict
`commons-transition/1` fact at the current tick. That fact names both physical
base hashes, both rule versions and the exact source native-world hash.

Admission requires the original Greenfield base and quiet serializable native
controllers. Existing body poses, entities, contents, action records, graph
aliases, action counters, Souls, ownership and private instructions survive.
New fixture/region IDs and kernel identities cannot replace existing things.
The actual detached candidate runs the native physical invariants before any
write. A body occupying a new bench refuses the transition; it is not displaced.
Explicit obstacle overrides need a separate migration and are currently refused.

The event and `worlds.rules_version` update share the existing sequencer's SQLite
transaction. Queued admission rechecks current physical and kernel facts. A
failed header write rolls both back. Actual worker exits after event insertion,
after header update and after commit demonstrate the two rollback boundaries
and replay recovery after commit but before physical application. Snapshot and
complete genesis replay reach the same native and kernel state.

The reader validates the final replayed rules against the durable world header.
A missing transition cannot be hidden by starting directly from the new scene.
Readers with the current strict history guards reject the new header before
constructing an incompatible world. **Rollback requires such a compatible
reader build; this is not a claim that an arbitrary older deployed binary is
safe.** The old database/history must remain recoverable until integration.

The recorder seals its old partial take at the checkpoint and starts a new take
with the new captured render base. Stored older takes and their captures retain
their original bytes; no take straddles the scene boundary. The new anchors are
derived from actual native regions/fixtures. Existing kernel anchors are retained.
Minds reconsider the changed public situation without inventing instructions.
