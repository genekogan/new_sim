# Retained commons-to-shore transition

The explicit retained reader starts from the original dry commons genesis and
replays existing provisions and both kitchen recipes. It adds the connected
native shore only through a guarded `rules.retainedCommonsShore` checkpoint.
This is a separate reader from the fresh-only connected-shore factory.

An exact quiet boundary is required: no programmes, departing actors, unverified
active actions, obstacle overrides or colliding region IDs. A detached native
graph retains every existing body, entity, region, record, RNG and action counter;
only the physical base and two new shore regions change. New ground, bank and
water reuse the previously qualified connected shore controller and source bed.
Actor positions, prepared food, personal items and sleep areas are not replaced.
The native graph is restored and checked with the new physical invariants before
acceptance. Full source/rules/base/world hashes and geometry source identity are
recorded. The world header and named fact commit atomically. Committed fold faults
use exact reboot. Station-history carry remains unsupported and refused.

New `retained-shore/1` physical rules enable the qualified blocked-walk policy
prospectively. The shorter explicit rule address preserves the existing200-character
render-reference limit. Old rule addresses/captures remain readable. New captures
compose actual shore geometry with existing `scene.provisions` and versioned
`scene.kitchen`; they do not drop resting areas or move stock. The snapshot reader
validates binding/policy/resource flags and retains exact current programme state,
including in-progress swimming. Older physical/kitchen readers refuse the new
history; rollback requires this compatible reader and preserves the checkpoint.

Ordinary owner go-to cards use native walk → wade → swim → tread through the dry
gate and return using the same controller. Occupied hands/seat/load/body and
unqualified wet-domain actions retain the existing explicit refusals. No teleport,
model-dependent replay, fluid force simulation, arbitrary climb, boat or new
body-family capability is introduced by this transition.

Native evidence preserves actual completed food preparation and all other stock
through transition, swims and returns, resumes mid-swim tick-exactly, preserves
old emitted take/capture pairs, rejects forged source/policy and busy/occupied
region boundaries. Eight separately invited human owners retain bodies/resources
and earlier canonical history; ordinary owner HTTP journey and return work, with
exact native/kernel/needs snapshot and genesis replay using fake models/$0.
The old engine hot take window is bounded; old pairs must be archived when emitted,
not assumed to stay in memory indefinitely.

Earlier prototype failures remain recorded: long rule address exceeded existing
capture limit; the initial history assertion used expired hot chunks; exact9m
comparison differed by2e-15m after native interpolation. The corrected scope
uses the original rule bound, actual archived pair and sub-nanometre terminal
position check. No actor coordinates or accepted data were altered to pass.

Source/native component readiness does not activate the running PM world. The
selected installation closure, source counterparts, actual retained-world quiet
readiness, private/public consumer checks and real-player observation remain
required. API/clock availability must be preserved while waiting; the food
readiness correction does not grant permission to force a shore boundary.
