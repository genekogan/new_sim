# Finite newcomer resource checkpoint

Core source implementation, default unselected. `commonsNewcomerResourcesFactory`
wraps the exact existing factory/genesis. `installCommonsNewcomerResourcesV1`
accepts authored placements and appends one named rules fact, with a guarded
header update and native/kernel adoption. No main entry or preview flag selects
this reader yet; the current Root, original eight Souls and finite delivery B
remain untouched.

Lifetime slots start at nine and append through thirty. Each new slot receives
one fresh bowl with one finite meal, one spoon and a ground sleeping region.
Consumption, old objects, bodies, ownership and prior facts are preserved.
Retirement never recycles a slot. Later checkpoints can append remaining slots;
there is no stock refill, periodic replenishment, new birth policy or economy.
The existing birth watcher catches up after the checkpoint and assigns cards to
actual eligible owners using the canonical birth order, including retired births.

Native preview uses a detached resumable graph, collision/invariant checks,
nonoverlapping rest rectangles and ground-clearance sampling through the rest
envelope at 0.25 m spacing plus meal/utensil/return positions. Stale or forged
adoption, identity collision, unavailable reader and capacity overflow refuse.
These checks do not qualify decorative vegetation or guarantee a route remains
open after future actors/construction arrive. Actual native activity admission
continues to enforce reach, hands, support and occupancy.

The first checkpoint replaces the long `+commons-provisions/1` header marker
with `+cp/2`, keeping the 200-character limit. This is a deliberate reader epoch:
original provisions remain active and unchanged, while the new snapshot/state
hash includes the ordered newcomer checkpoints. The wrapper converts only that
marker for its retained origin reader. Snapshots retain the original reader's
state hash separately; final restore checks the complete new state, identities,
rest geometry and checkpoint ordering. Old readers refuse new snapshots/headers.
The same complete reader is required for keeper/rollback after adoption.
