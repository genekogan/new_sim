# Stable camp resource bindings

The old camp pack chose personal mats, bowls and spoons by the current sorted
cast index. An actual local reproduction with Alice/Bob followed by Aaron gives
both Alice and Aaron mat-1/bowl-1. Existing cards remain immutable, but new supper
cards can also bind the wrong self/host utensils after the population changes.

The pack now derives existing affinities from bounded original world-mint
evidence keyed by actual world and Soul IDs. The canonical card hash must still
match. Removing a card or changing display order does not erase that source.
An older imported kernel/deck can supply its existing world cards when original
mint evidence is absent. New ties use the cast ordering only once to select an
unbound present resource set; the new logged cards then preserve the binding.

No card or physical resource is rewritten. Existing shared/conflicting history
is reported through `resourceIssues`, never silently repaired. Missing resource
references preserve the historical affinity and remain an explicit issue. A
new resident without an unbound mat/bowl/spoon set gets general activities but
no invented personal sleep/meal/utensil recipe. This is not an admission-capacity
promise or a population/ownership rule. Physical support, free hands, traffic,
route and native reservations still decide whether an activity can run.

Population refresh now adds new peer supper affordances to old residents too,
so restart does not invent an additional layer of cards. Existing card definitions
and hashes stay unchanged, and an ordinary population refresh does not redeal an
existing removed card. Legacy restart behavior for removed world cards remains
a separate pack-policy issue. Supper self and host resources use their stable
bindings; a new recipe is not minted for two identical resource affinities.

Six cases cover the old-source reproduction, newcomer/history/peer bindings,
snapshot and genesis reconstruction, missing fifth resources with continuing
general activities, removed-card evidence, actual-ID versus display-name scope,
and actual two-owned-body distinct-mat execution. The physical probe uses explicit
trusted logged fixture decisions, not ordinary compiler/autonomous qualification.
Old source is frozen in the test fixture; only its relative imports are rebased.
The native engine/world/card/lifecycle/SQLite paths are real; dev-auth is local,
minds/spend are fake/$0, resources close, no network or live DB is used.

Final affected binding/living/construction checks14 PASS and scoped server
ES2023 types exit0. Initial2/3 failed because a restarted pack learned new peer
cards that the live pack skipped; refreshing the live population closes that
actual semantic difference rather than weakening the hash assertion. Native
sleep fields required a native-type boundary in the fixture. These failures
remain in the execution receipt.

This is a prerequisite for the approved eight-Soul Mars expansion, not that
expansion's completion. The default registered personal registry remains four.
Eight actual owned bodies, additional validated resource sets, datum-preserving
upgrade, upper-floor/tread/support admission, mat top/contact, artificial water,
material inventory and reversible assemblies still need their own native and
consumer evidence. The registry is a future integration hook; presence of named
references does not qualify geometry or action capacity. No first-loop supplier,
default scene/bootstrap, root dependency, main or release changes are included.
