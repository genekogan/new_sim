# Actual self-location for the controller

The optional `connectedCommonsLocationFactory()` gives the compiler, built-in
mind, owner and paired agent the same actual body location. A Soul aboard a boat
is described as aboard the boat in the water region, rather than still at the
kernel's older commons relation or immersed in the water beneath the boat.
Boarding, seated travel and exit remain distinct. This is a read-only observation;
it never invents a kernel move or grants traversal, pilot control or ownership.

## Version and schema

The fresh `body-location/1` rules extension has its own complete hashed physical
base and adapter binding. Existing shore/boat/helm factories and their replay
addresses remain unchanged. No default bootstrap, old history, migration, main
candidate or release is changed. The same geometry, appearance and native
controllers are used; only this fresh factory enables the observer and changed
controller context.

`packages/engine-contract/src/body-location.ts` publishes a strict bounded codec:
actor/tick/base, exact root, current native region, actual container/passenger
frame and supported transfer, plus recorded shore contact. Current level and
smallest matching native polygon resolve region overlap deterministically. A
region is a geometric label; it does not certify a whole foot disc, floor,
interior admission or route. No world ontology is defined.

Boat frames are checked against the actual native occupancy and connector path.
Shore contacts must agree with current native geometry/root, including datum,
IDs, depth, bed height, normal, mode and submerged upright-capsule height. An
XZ water region alone never implies immersion. A seated passenger has no shore
body contact; a swimming body in the same region has a qualified contact.
A physical base identifies geometry, not a logical world or owner. Existing
request/world/Soul/owner/token scope remains the authority boundary; this
observation must not be treated as a transferable capability.

The Engine observer has three explicit states:

- `undefined`: this observer is not installed; legacy context and response stay
  unchanged and the new private field is omitted.
- `null`: current physical placement is unqualified; private `physical_location`
  is null and the mind/perception says “physical location unavailable.” The
  compiler receives that uncertainty rather than treating the kernel place as
  actual physical truth.
- A validated object: owner/agent/status/mind/compiler use the same current
  physical placement. Status region follows that current observation.

The compiler distinguishes physical placement from the separately retained
kernel relation. Physical entity/container IDs are native references; they do
not become new kernel Thing IDs or permissions. Dynamic placement is in the
uncached request context; the existing cached grammar/system prefix is retained.
No model routing, paid budget or account/invitation/token policy is changed.
Tagged physical-place wording participates in the mind's call fingerprint. A
meaningful place-description change can therefore prevent an unchanged-context
skip; raw coordinates and tick do not trigger a new call on every movement.
Legacy contexts omit the tag and retain their original fingerprint.

## Remaining scope

This qualifies current region, boat occupancy and shore-contact observation in a
fresh local world. It does not implement general kernel vessel/floor membership,
stacked-support admission, moving platforms, arbitrary containers, additional
body-family activities or walk/talk composition. Synthetic compilation and
explicit evaluation do not qualify model language quality, autonomous population,
real Auth, installed agents, cohort/device capacity, UI, combined rendering,
OS-crash/old-binary rollback or production. App/World/PM counterpart review and
Gene's main/release handover remain separate gates. These remaining requirements
stay on the active Core program.
