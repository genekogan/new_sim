`Souls.create` checks the schema, active per-owner row count (default 5, across worlds in the same Db), and active case-insensitive name uniqueness within the selected world. It writes an owned row before awaiting an ephemeral `birth` queue entry. HTTP returns `{ok:true,soul:{id,name,description,entityId}}` after that await. This is not a typed placement/admission receipt and has no idempotency key, world-wide reservation, or capacity count. Invitation permission does not reserve space. Native seed creation bypasses the per-owner count guard; that internal flag grants no public creation policy.

The sequencer appends birth before applying it. The fold calls `spawnHuman` before adding the kernel Soul; the host adds a Mind after the fold succeeds. The native adapter searches rings 0 through 5 around the configured arrival (up to 91 candidate positions), excludes existing human centres closer than 0.8m, and requires at least one successful walk plan to the configured reference or arrival. It then installs the body, Soul association and present change. The candidate search is not a population limit: geometry and moving bodies affect it. An existing entity ID is returned without verifying its Soul association.
