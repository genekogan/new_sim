# Current private authority on the existing WebSocket

PM-T024 identified an actual connected04 failure: invitation and native Soul
admission completed, but the real browser kept its initial uninvited/empty-owned
Me. Hub refreshed its server cache without publishing that change; the SDK/App
updated ownership only on welcome. This fixes the producer and SDK seam. App's
useSim consumer and PM's next affected combined run remain separate.

The lifecycle-enabled Hub advertises strict `me-live/1` in the normal welcome:
one fresh connection ID/subject and revision1. Dedicated private `{t:'me',view}`
updates bind world, server epoch, that exact hello scope and the next revision.
They contain the current canonical Me or explicit null. Me owns logical Soul
IDs; the HTTP Me roster contains richer objects. Native/public bodies and names
never establish ownership.

Existing `refreshMe` publishes invitation/retirement/account changes directly.
Existing two-second stats/authority refresh publishes asynchronous native
readiness and revocations. No new timer, worker, world event or polling object is
introduced. Ordinary updates do not resend welcome, reset the public replica,
clock/anchor, station, transport generation or history. Current DB invitation,
role, world, owner and actual lifecycle control-ready predicates are rechecked;
pending allocation is not usable ownership.

Private updates cannot use public broadcast. Backpressure closes the affected
private channel rather than silently dropping a revision. Current-user deletion
publishes null, preserves public viewing and clears the accepted subject; a
recreated row cannot silently reauthenticate that socket. Fresh hello is needed.
Pending/newer/closed-socket authentication is generation-fenced, so an older
token response cannot replace the newer subject or publish its private history.
Invariant failures remain contained/visible under the existing private-view
error/close path.

The SDK publishes `Connection.me`, `meSession` and `Handlers.onMe(me,scope)`.
The scope includes its local transport generation. Initial welcome remains
`onWelcome`; ordinary private changes use `onMe`. Valid updates refresh cached
welcome.you without emitting another welcome. Consumers must use current Me and
current world/socket/subject scope, and invalidate old private request generations
and cached private views when authority changes. App owns that UI integration.

The SDK rejects foreign world/epoch/connection/subject frames and ignores
duplicate/older revisions. Invalid/current gaps clear private authority and
require a fresh connection; queued frames cannot regrant it. Socket replacement,
close and fresh welcome clear previous private authority. Callback data/scope
are detached on incremental delivery. Old unconfigured Hub/welcome behavior
remains; old consumers cannot apply the new updates without their counterpart.

SQLite, registered native commons admission, the real TCP WebSocket Hub and the

the original authority/stat refresh, without a harness rehello/refreshMe call or
injected Me/body/ownership. Foreign/anonymous private negatives pass. Deleted-user
null/public continuity and overlapping/closed async hello checks pass. Controlled
buffer-counter injection checks slow-private-channel closure, not a network-load
benchmark. SDK fixtures cover malformed/foreign/late/gap/legacy/detached data.
