## What I did
- `apps/server/src/god/map-notices.ts` (new): pure planning + delivery, using G1's notice shape (`bridge.notices.notify`,
  `kind:'god-change'`, `native: true` so native minds get it in `recent` through the logged `godNoticeV1`).
  - Visible changes only: added / removed / moved / re-made things (def, pose, params, shape, seed, rebinding), the
    outermost one speaking for its subtree. Not state-only edits, renames, owner/schedule/price, bodies or things in hands,
    or things a walk-out set down.
  - Who: residents within 30 m of a change (its footprint, now or where it was), or whose owned / `lives-at` / `works-at`
    thing it touched; minus residents a G1 walk-out told (moved, stopped or stuck) in the same request.
  - One sentence per request: build title (+ say), else the batch note, else "The god built a house at Green field." /
    "… and changed 3 other things by the fountain." (`at <place>` / `by <named thing>` / `near you`).
  - Spam bound: ≤ 1 per resident per minute; sooner ones merge into one later notice on the 20-tick cadence.
  - Construction: "The god started building X nearby; it is closed until finished." (residents inside a closing site are
    left to G1's walk-out); no per-edit notices while the build is closing; "X is finished and open." at done (replaces
    an edit notice staged in the same request).
- `engine-bridge.ts`: plan in `prepareWalkouts` (non-dry), stage in `bodies.apply`, deliver on a microtask after the
  request; `onBuild` started/done; flush on tick cadence. `god.ts`: `apply` gets `{kind, note, build}` (act, revert, group undo).
- SKILL.md: two lines (notes help; ≤ 1/min). `eden-god.mjs` fresh.
