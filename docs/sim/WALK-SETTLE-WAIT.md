# Prospective final-walk obstruction reporting

`WorldHost.enableWalkSettleWaitV1()` accepts one `rules.runtimePolicy`
fact with `walkSettleWaitV1:true`. Repeated calls return the accepted fact.
The policy is absent by default and monotonic after acceptance. It changes
native execution only from that fact onward; old snapshots and replay retain
the old path. It adds `walk-settle-wait/1` to the canonical engine hash input,
retains the flag in the adapter snapshot configuration, and reinstalls the
derived runtime service on restoration, compaction and physical rebase.

At an arrived walker's final lateral recentering, an actual person or carried
load can obstruct the inward segment even when the destination is clear.
The old hard-separation fallback retained the safe pose and offset but discarded
that dependency, reporting an unnamed `settle` forever. With this policy it
retains the blocker and reports the existing native wait. Existing courtesy,
planner recovery, deadlock diagnostics and safe cancellation remain responsible
for progress or a truthful finite refusal. No separation tolerance, movement
budget, support, destination, duration or quiet/needs/night rule changes.

The retained Mars p440 counterexample is a sit approach followed by its original
120-second seated hold and stand. Detached qualification demonstrates that
programme's natural terminal execution; it does not demonstrate completion of
the pending external walk receipt. That requires Root's separate stage activation
and observation on a whole retained-history copy. No live activation is part of
this leaf.

After this fact is accepted, the minimum rollback reader must understand
`walkSettleWaitV1` and its canonical hash input. A pre-policy binary is not a
qualified rollback even if its factory recognizes the same base rules string:
its engine hash/continuation differs and the durable frontier rejects it. Code
rollback must retain the complete current data and choose a qualified reader;
never delete the fact or restore older data. The base rules string remains
unchanged, following the existing versioned runtime-policy convention.
