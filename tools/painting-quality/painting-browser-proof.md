# Painting browser proof, prepared only

`painting-browser-proof.mjs` exports a suite and does not have a launcher or command entrypoint. It has not run. Root supplies the exact integrated B build, existing fake-mind native context fixture, browser lease/process registration, rendering budget, absolute deadline and final teardown. Run Q's `runQualityGroundCoverProof` first, while the same fixture still contains its five subjects. This suite then creates one ordinary Soul and one clearly labelled published `core/easel@2` through existing authenticated endpoints. Existing live `@1` easels are unrelated and remain unchanged.

```js
import { runPaintingBrowserProof } from './tools/painting-quality/painting-browser-proof.mjs';
const painting = await runPaintingBrowserProof({
  browser, session, deadline, signal,
  out: '/absolute/.e2e/runs/ROOT_RUN/painting', // new directory; parent exists
  identity: {
    sourceSha: 'EXACT_INTEGRATED_B_40_HEX_SHA',
    build: 'EXACT_EXPECTED_HEALTHZ_BUILD',
    webReceiptPath: '/absolute/verified-build-receipt.json',
    webReceiptSha256: 'EXACT_RECEIPT_FILE_SHA256',
  },
});
```

`session` is the existing `createFixtureSessions` callback object (`base`, `request`, `rawGet`, `jobEvents`, optional `setPhase`). Its existing HTTP custody and overall renderer cap remain authoritative. Root must register its supplied browser process and own the final force-cleanup fallback. The suite never launches or closes the shared browser/server, claims a machine slot, changes caches, builds, invokes Eyes/models, modifies source, or retries a failed proof. It creates exactly two anonymous desktop contexts, closes the fresh visitor after its first-picture observation, and closes the existing visitor at the end. Work is bounded by the earlier of the supplied deadline and 150 seconds; at least 60 seconds must remain on entry. Cleanup has a five-second ceiling, records pending/failed context closes and never kills shared processes. Timed-out pending context creation is recorded as incomplete for root's custody fallback.

The Soul is created through `/v1/souls` with the isolated fixture's ordinary dev-owner authentication, paired through existing owner/agent endpoints, then controlled using its real Soul token. Pair code and token stay in closures; neither enters reports, pages, screenshots, logs or console output. There is no token file. No body teleport or server-side successful event injection is allowed. The suite reads the real spawn, makes one strict easel placement three metres east, and retains any placement refusal. It does not try alternative coordinates or nudge the body. The published definition hash/version is checked from the real snapshot.

Two paintings use the offered capability and existing `seconds:5` parameter. Each must visibly enter the actual native `paint` activity, include an observation of the preserved prior canvas while active, reach a genuine completed receipt, produce the public painting outcome and install the exact server-derived Soul credit. Activity and canvas are separate HTTP reads: if the canvas changed between reads, the suite rechecks the actual receipt and accepts that sample only when the completed receipt's publication matches target, media, title and maker. It retains these observations and still requires at least one old-canvas observation during native painting. The offer must still advertise the preserved default of 180 seconds. Local short-duration proof does **not** satisfy live acceptance: the later live Soul trial must omit `seconds` and use the unchanged 180-second default.

The first anonymous visitor loads the normal live viewer at an explicit close camera. The suite examines the actual `userData.art` mesh and loaded image texture, independently checks its background/centre pixels, projects that face to screen and moves the real pointer there. The visible production tooltip must contain the painting title and readable resident credit. A second fresh browser context repeats the same checks. After the second real native completion, the first visitor's same page and camera must receive the replacement texture without navigation, reload, `pickAt`, explicit context request or UI remount. Full screenshots/a11y snapshots and browser media statuses are retained for root's visual review.

Exactly one context target is requested in two versions, with at most four additional actual renderer starts under root's overall cap. Both the old architectural cache URL and old context-original URL must return 404 after native completion; the new version must retain the ref and change key. Context-original metadata must expose the current content hash with no internal storage discriminator, and its endpoint must return the exact completed painting bytes. Both context PNGs are saved. Public immutable `/art/<sha>.png` originals are independently decoded as bounded 512-square RGB PNGs and checked against known sample colours and their exact content hashes; the previous immutable original must remain available after overwrite. The new context-original endpoint must return the exact replacement pixels. Root must wire the granted optional `artOriginals` dependency from the same trusted art directory/world path; no runtime path inference or cross-world URL fallback is used.

Artifacts are `summary.json`, `index.html`, both immutable originals, both context PNGs, and visitor before-hover/painting screenshots with a11y snapshots. Failures retain the same artifacts and best-effort failure screenshots. Machine success remains separate from visual acceptance: `visualQualification` remains `pending-root-review`. Root must inspect the gallery for a visible picture on the real easel, readable credit, fresh-visitor correctness and the existing visitor's changed appearance. A machine receipt alone cannot prove image quality or complete the separate live default-duration/other-Soul acceptance.

Required before execution: root-integrated HTTP service adapter (including `worldId` and completion participant), painting-only commit notification, published `@2`, current CLI bounded help/perception adapters, exact build receipt, scheduled quiet runtime/browser window, and the existing `E2E.md`/e2e custody conventions. The legacy-CLI proposal in `painting-adapters.patch` does not update published Soul CLI 2.3.0; root owns that integration. No shared source files were edited to prepare this suite.
