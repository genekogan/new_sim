# Mars water (W5), October 16

A world patch for **my-mars-college-2026-3**. It needs the server change on branch `lane/mars-20261015` (commit "W5 water provisioning"), and the viewer build for the damp soil.

**What residents can do.** Water is finite and moves by hand:
- **Draw water.** Pick up the watering can and draw water at the tank (`object:<tank>:draw-water`). The tank loses exactly the litres the can gains.
- **Water a bed.** Walk to a garden bed and water it (`object:<bed>:water`). The can loses what the soil takes, and the bed's damp patch spreads.

**Honest refusals.** Each is offered as a blocked capability with a plain reason:
- `water.no-vessel`: not holding a can.
- `water.vessel-full` / `water.vessel-empty`: the can is full or empty.
- `water.source-empty`: the tank is empty. "It needs a water delivery before anyone can draw from it."
- `water.plant-wet`: the bed is already well watered.
- `water.no-source`: a catalogue can's own `fill` is refused unless a tank stands beside it.

**Refilling.** The Mars tank has no magic fill. It refills only by a delivery: the creator sets `level` via Godmode `set`.

## Contents

`defs.json` holds three world-local defs, generated by `tools/mars-rotation/water-defs.mjs` from the core kit:

| Def | What it is |
|---|---|
| `mars-water-tank@1` | The core raised tank: 1,500 L, gauge, no fill/empty. |
| `mars-planter@1` | A raised bed. `moisture` 0..1 (8 L soaks it from dry); its damp patch is kit role `fill`. |
| `mars-watering-can@1` | The core can (10 L), tagged `item`. |

The `item` tag matters. The core can lacks it, so the entity world refuses to put it in a hand (`slot.incompatible`, see Findings).

`spec.json` places four things beside Freeside's hydroponic cart:

| Name | World (x, z) at bearing 90 | Notes |
|---|---|---|
| `water-tank` | (101.6, -38.6) | 0.6 full = 900 L |
| `garden-bed` | (99.0, -39.6) | |
| `garden-bed-2` | (99.0, -41.1) | |
| `watering-can` | (97.9, -39.5) | empty |

The tool turns these positions onto the live campus bearing, which it reads from Mimos, so the patch can go before or after `mars-rotation-20261016`.

## Apply and rollback (release owner)

Same tool and rules as `../mars-field-20261016/README.md`. Use Node 22.20.0. The credential is read by path only. Keep the receipt outside Git.

```sh
N=~/.nvm/versions/node/v22.20.0/bin/node; T=<worktrees>/lane-mars/tools/mars-rotation/add-patch.mjs
S=<worktrees>/lane-mars/worlds/patches/mars-water-20261016/spec.json; B=https://sim.eden.art/worlds/w/my-mars-college-2026-3
$N $T --spec $S --base $B --receipt /ABS/PRIVATE/mars-water.receipt.json                                  # review, no token
EDEN_GOD_TOKEN_FILE=<path> $N $T --spec $S --base $B --receipt /ABS/PRIVATE/mars-water.receipt.json          # preview
EDEN_GOD_TOKEN_FILE=<path> $N $T --spec $S --base $B --receipt /ABS/PRIVATE/mars-water.receipt.json --apply
```

- **Interrupted apply:** run again with the same receipt and `--recover`.
- **Rollback:** run with `--rollback` (review), then `--rollback --apply`. It removes exactly the four things by id in one guarded batch (`expect` versions).
  - It refuses while a resident holds the can; put it down first.
  - Residents having used the water does not block it.
  - The defs stay defined, unused.

## Findings

1. **Catalogue carryables without the `item` tag** are put in the hand by the engine, but the entity-world write-back refuses them every tick (`slot.incompatible: carry accepts tags item`). Seen with `core-watering-can`. Other carryable core defs that lack the tag (e.g. `core-potted-plant`, `core-lantern`) likely do the same; not checked. Viewers keep drawing such a thing where it was picked up, while the Soul's receipt says it is held. This patch avoids the problem with a tagged copy of the can. The general fix belongs to the Godmode/world-compiler owners: treat `components.carryable` as an item for the body's carry slot, or tag those defs.
2. Watering is a state change only. Beds do not dry out over time, and nothing grows. Drying could be a schedule on `moisture`. Growth and sowing are new verbs (big).
