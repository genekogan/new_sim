# Lab synchronous executor-fault containment

Future alpha candidate based on `2534319`, branch `codex/lab-executor-fault`, isolated worktree `<mars-worktrees>/lab-executor-fault`. Only `app/lab/sim.ts`, the new native regression file, and this report are owned. No activity, Runtime, UI test, scenario declaration, rig, camera, backend or deployment change was made. Root's sustained execution guard remains unchanged.

## Reproduction and repair

An unexpected synchronous throw from an action step or `scenario.tick` previously escaped `LabSim.advance()` into the RAF caller. A tick may already have advanced some actors or published effects before the throw. There was no explicit halt explanation and later callbacks could retry the same faulty code. Deliberate native fixtures reproduce this without pretending the exception is an ordinary expected refusal.

The driver now contains synchronous faults after a valid Runtime exists. Stage labels identify runtime stepping, authored tick/start/admission/completion/expectation, and Lab observation callbacks. `lab.executor-fault` records the scenario, current tick, original standard Error name/message/stack (or explicit non-Error thrown text), and an `unknown-partial-execution` state diagnostic. The human-readable diagnostic and log explicitly require a fresh Reset. Original action statuses, records, effects, active claims and world state remain as actually left by the throw. No rollback, cancellation, resource release, synthetic completion or unsupported cleanup is attempted.

Play/Step already consume the shared `halted` field and are disabled by the existing panel when its render completes; the separate unguarded render callback gap below limits this UI claim. Later Lab automatic/manual ticks and authored dispatch stop. `done()` does not claim successful completion during quarantine; `checks()` returns a visible failed fault check without retrying the faulting scenario callback. A fresh successful load constructs another Runtime, clears the fault and increments the existing epoch. It does not falsely clean the discarded fault world or promise to resume its actions.

Ordinary named action refusals still retain their original records/diagnostics and allow unrelated actor progress. First invariant corruption remains the primary reset-required halt. If the first invalid tick's observation callback also throws, the original invariant and unexpected exception are both retained: the invariant remains primary, with executor details and a separate full exception log. Exceptions are not relabeled intentional or successful.

Every unexpected-fault fixture reports failed visible checks. Reset/navigation returns to a fresh valid native world; old fault-world claims are honestly retained in the discarded reference.

Viewer TypeScript, owned-file type-aware lint, new-test formatter and git diff --check pass. ## Separate pre-Runtime gap and limits

A normal native load probe confirmed a separate builder failure boundary: starting `wall` at epoch 1/hash `d64211aee273005f871116d9b3561aa7f726aba427947bdb0346acfa93b4f1ee`, a deliberately throwing replacement builder leaves the **new scenario name with the identical old Runtime/hash**, epoch 1 and no halt; the exception escapes before this guard. Receipt: `.cloudflare/lab-executor-build-gap.json`. This was reported to root and excluded from this repair. Proposed smallest separate review: construct the next Runtime locally before atomically assigning scenario/Runtime and publishing reset/epoch, retaining the prior pairing on build failure. Initial-page no-prior-world, fetch/prepare errors and load races need their own explicit review; no transactional loader or fallback world was added here.

This boundary is Lab synchronous hosting containment, not global Runtime/backend quarantine or complete world recovery. Direct Runtime submit/cancel paths (including existing activity HUDs/hook controls) are not fenced here. Arbitrary renderer/camera faults outside Lab callbacks, asynchronous rejections, malformed object shapes and failures before a valid Runtime exists are outside the proved contract. The driver preserves unknown partial state for explanation/reset; it cannot certify support correctness or safe continuation after an executor throw. No browser, performance, full gate or deployment was run, and actual visual fault/reset interaction remains unproved.

A read-only panel review found direct `s.admission?.(sim.rt)` evaluation in the Expectations class name and direct `s.hud(sim.rt)` rendering outside this guard. A throwing admission callback can therefore be retried by React after native quarantine and prevent visible Reset. The native completion/expectation no-retry tests prove the guarded driver reads, not universal React containment. Executor/tick fixtures without throwing render callbacks can use the existing halt UI, but browser proof remains absent. Root was notified; the smallest separate panel repair is to skip these callbacks while halted and review guarded adapters for healthy render reads. No panel edit is included in this owned three-path change.
