# Table cleanup HUD

Bounded HUD implemented from future candidate `d90c37c` in isolated branch `codex/table-cleanup-hud`. Only `viewer/app/lab/table-cleanup-hud.tsx` and this report are new; shared registry, scenarios, panel, hooks, renderer and tour remain parent-owned.

Export `TableCleanupHud({ sim, refresh })` and mount it alongside existing Lab HUDs. It returns null outside `table-cleanup` and `table-cleanup-rotated`. The parent must wire those scenarios and register `TABLE_CLEANUP_ACTIONS`. Start uses the unchanged three-item `tidyTableBinding()`; the rotated preset must rotate the complete physical setup π/2, matching `tidyTableWorld(Math.PI / 2)`. Ordinary Direct tidier away submits `walk_to` for tidier to [-5,-5] in the base preset and [5,-5] in the rotated preset. The HUD never edits entity pose, support, hands or contents.

The panel uses authoritative `tidyTable.plan`, `tidyTableControl.plan`, and `readTidyTable`; it follows the exact active task or its retained readout. Start, Pause, Resume and End admit only applicable state. It reports actual completed/remaining transfer IDs and declared source/destination slots, current physical transfer/return phase, actual item support and finite bowl contents, concrete wait/refusal, and a named Resume admission failure. Completion distinguishes full transfer completion from early End. Feedback is tied to the current Runtime so Reset does not show the prior world's acceptance message.

Controls submit immediately from click handlers, with current Runtime/exact task/admission checked again at click time. Pending controls for that task prevent overlapping UI requests; no state effect, timer or deferred UI command queue submits later. Direction guards an already-active top-level tidier walk while preserving player intervention during ordinary child walking. Start checks the live task again and uses `preempt: false`. Underlying runtime remains authoritative if the world changes between renders.

Visible scope explains that tidying moves the same bowls/book/contents, without washing, deletion or replacement. Pause/End use only the declared source or destination support; if both refuse, actual held ownership persists and the concrete refusal is shown. Play must advance safe release; global Pause freezes time. Explicit Resume continues remaining same objects in this Runtime; Reset creates a fresh hypothetical world. Active reload restoration is not claimed.

Validation: `oxfmt` on the new HUD, `npm run typecheck`, and focused `oxlint app/lab/table-cleanup-hud.tsx` pass. No browser, performance or full gate ran while the parent owns their serialized slot. Parent integration must verify the mounted HUD, physical carrying/support visibility, rotated direction, controls, diagnostics and combined release candidate in the browser. Engine control lifetime and release behavior retain the existing 19 focused cleanup tests; this HUD adds no engine or physical-action behavior.
