# LM-027 — ambient re-adoption after directed work

Candidate atop converse member-return hooks. Ambient exec records plain return intent
only when a directed instruction addresses an eligible member. It waits for the outer
directive, then checks current ownership/task, construction grip, in-hand small items,
and the original region hash. Successful admission uses the ordinary 0.9 m/s child
walk into that region; no relocation, reservation transfer or resource release occurs.
A newer explicit instruction supersedes the intent even when that instruction refuses.
Failed/cancelled directives, busy/held people, expired ambient duration, changed/missing
regions, unavailable targets and failed routes produce named ambient.return-skipped
marks. Manual cancellation of an ambient walk remains permanent release.

The default snapshot graph now supports ambient_wander after exact tests establish
its plain exec, child-record aliases and checkpointed RNG. Four pause phases continue
with identical per-tick world hashes/events: ordinary walking, initial pause, waiting
on a directive, and a physical return walk. Malformed/missing return intent, missing
directive and duplicate member state refuse as snapshot.ambient-invalid. No duplicate
actor ownership appears. Existing unsupported live construction codecs remain unchanged.

Validation: six new focused tests, three existing ambient/determinism tests and source
scan pass (10 total); tsc/lint pass. New cases include held load and small in-hand cup
support retention, newer groups, failed/cancelled commands, region deletion, an idle
ambient participant, and manual cancellation. Full integrated gate/browser verification
remains pending. No pins or historical values changed.
