# Read-only Lab camera hooks checkpoint

Requested by Gene's separate autonomous-camera task; starts from classroom/workstation candidate a4078c6. Camera policies, provider decisions and editorial behavior remain in that task.

- `__marsEngine.scenarioEpoch` increases on every successful scenario load, including same-id/same-tick reset. Invalid load is not a new world.
- `camera(position,target,fov?)` accepts optional finite20–80 degree FOV. Invalid vectors, coincident position/target or invalid FOV return named `camera.lab.invalid-pose` / `invalid-fov` diagnostics before any render mutation. Existing two-argument calls remain supported; `cameraPose()` remains the getter. This changes render controls only.
- `cameraGeometry()` returns a frozen detached snapshot `{schema:'mars-lab-camera-geometry/1',scenarioEpoch,epoch,scene,fixtures}` or named geometry-unavailable diagnostic. Scene is the effective spatial scene, including current static fixtures/components and contributed support; fixture obstacles are additionally indexed. The snapshot is cached by Runtime identity, scenario epoch and spatial epoch. Actor movement alone does not invalidate it; moved static furniture does. Spatial synchronization refreshes derived navigation caches without changing authoritative entities/actions/claims. Moving people/carried loads are not static geometry; use existing pose/component readouts alongside this snapshot. No promise of support for arbitrary furniture edits is added.
