# Empty camp-chair physical mover prerequisite

Read-only bounded design pass, 2026-09-29. Source inspected at released main f0e3851, `<mars-campus-repo>`. Existing activity source in stow-items ffc90e8 informs held-item preparation. Root's release17 gate/candidate is untouched. No implementation, tests, browser or new helpers.

## Decision and first supported outcome

Build one registered `move_fixture` action for an empty, unreserved, grounded hypothetical camp-chair, carried upright by one free standing person across one ground room and set upright at an explicit `(x,z,yaw)`. Keep entity.kind/category fixture throughout; preserve its seat ID, definition, dimensions and mass. Table movement is a later extension. Begin with room setup before the event; a reserved/occupied classroom chair refuses. Active-session authorization/local seat rebinding comes after this physical prerequisite, not silently through actor preemption.

This is feasible with existing rigid-formation geometry, support and cancellation mechanisms. It is **not** safe as a thin wrapper calling today's carry on a temporarily relabeled entity. A bounded carry executor/profile seam and load-invariant participation are prerequisites. If those cannot be introduced without changing construction semantics, stop rather than shipping a parallel unvalidated mover.

## Precise reusable pieces and blockers

1. `carry/formation.ts`: SE2/Formation/Disc, carrierSpots, worldDiscs, gripError, entityFrame, poseAt/toWorld and carriedPose provide load/carrier geometry from catalog dimensions; `planner.ts:1–29` plans deterministic whole-formation trajectories; `sweep.ts:1–24` conservatively checks load and body swept cover. These have no required fixture→component conversion. Geometry helpers currently derive formation from `AssetDef.handling` and construction orientation defaults; expose one pure geometry builder taking validated handling and explicit carried/set-down orientations, with the existing builder using unchanged defaults.
2. `carry/validate.ts:124–158` rejects fixture kind and requires stored/staged ground component. Ground planning after that already removes the mover's own obstacle, validates pickup/carrier stations, exact set-down footprint/floor and route (`:158–214`). Reuse those pieces through a narrow validated profile, retaining original component admission. `laidIssue:79–101` computes a fake component solely for footprint geometry: remove that semantic assumption in the reusable geometry helper, not the real world's fixture identity.
3. `carry/actions.ts:19–39,190–218,294–324,382–410`: ordinary gather sub-walks → held lift transition → continuous accelerated formation motion → checked set-down → release. Reuse its state machine rather than duplicate its movement controller. It assumes `laidPose` (flat) and transition finals stored/staged, so an upright fixture profile must supply validated upright set-down pose and original resting phase restoration. Its physical interpolation and speed bounds should remain unchanged for legacy carry.
4. `carry/actions.ts:443–490`: gather cancellation stops real walkers; lift cancellation lowers to original pose; moving cancellation validates the current set-down footprint and either lowers safely with deferred cancellation or refuses carry.cancel-unsafe while retaining load support. Reuse exactly this safety structure. No terminal fail/release if a fixture would be left suspended; no invented empty safe spot.
5. `world/types.ts` already allows generic support `{kind:'held',by:[actor]}` and human.grip. `runtime/invariants.ts:152–180` checks held support for every entity, not only components. `spatial/service.ts:14–18` excludes any entity with carried phase from static obstacles; restoring no phase on a grounded fixture restores its catalog obstacle. Runtime parent-child claims and cancellation infrastructure need no redesign for this first standalone action.
6. Required narrow coverage changes: `carry/actions.ts:82–97` activeLoadDiscs filters component and verb carry; `carry/invariants.ts:20–57` integrity filters components and reconstructs construction formation; `runtime/invariants.ts:75–87` carried-load motion bound also filters components. Recognized movable fixtures must join these checks and walker load-disc avoidance, using the same authoritative validated catalog geometry. A new mover without these changes would disappear from moving-load avoidance/invariants even though ordinary held-support checks pass. Do not globally treat all fixtures or arbitrary unknown actions as carry loads.
7. `runtime/snapshot.ts:111–116` already refuses dropping an action whose reserved entity is carried or whose actor task grips a load. Mark active move_fixture explicitly nonresumable initially; do not weaken unsafe-drop behavior. Grounded completed fixtures persist normally.
8. Visual prerequisite: `app/engine-view/fixtures.ts:299–317` copies fixture poses on ticks; `:341–343` only animates fires, so movable chair interpolation needs a tiny last/current pose path for moving fixtures. `app/lab/lab-view.ts:54` reach fallback only queries components; `engine-view/humans.ts:414–424` tracks all gripped world entities, but `:1298–1322` slotPoint recognizes construction grips. Supply authored fixture grip points through that existing read-only target path (or a fixture-aware nearest-point adapter), not a new animation/movement controller. Finger precision remains deferred, but an obvious hands-in-lap carry is not acceptable visual proof.

## Minimal authoritative capability and schema

Add one machine-readable `capabilities.fixtureCarry` on camp-chair. Reuse existing catalog handling/grip conventions where compatible, with one authoritative geometry definition rather than an ID lookup table: crew bounds fixed [1,1], explicit upright carried and upright ground orientations, carry height, physical grip layout/hand targets and load/collision dimensions derived from existing size/mass. Validate the capability at catalog/planner admission. Chair stays 0.55 × 0.85 × 0.55 m, 4 kg hypothetical fixture (`world/catalog.ts:247–255`). Do not add small/in-hand-item capability to the chair. Existing handling carryPose flat/edge alone cannot express upright placement: generic laidPose would tip the chair onto its side.

Public bounded intent: `move_fixture {actor,fixture,to:{x,z,yaw}}`. No arbitrary dimensions, grip offsets, crew list, access link, level, fold/unfold, pitch/roll, placement mode or automatic target selection from callers. Internal reuse may adapt actor to a one-member crew; validated program stores original grounded pose/phase, immutable physical binding, target, formation and trajectory. Public readout should expose gathering/lifting/moving/setting-down/releasing/blocked, fixture/actor, destination, waiting reason, diagnostic and whether a safe stop is still pending.

Resource set: exclusive actor, both actor hands, entity fixture, and **all** canonical `slot:<fixture>#<slot>` keys. Check actual occupancy/transition and reservations before execution; show named move_fixture.occupied / move_fixture.reserved / unsupported / actor-hands-full rather than forcibly cancel a seat/session. Normal Runtime conflict diagnostics still apply. Prefer the action's non-preempting admission policy so moving furniture does not implicitly make a seated classroom worker stand. Actual small held bowl/spoon requires the explicit stow path first; construction grip also refuses. No intent substitution.

## Physical/support constraints

Ground level0, flat authored room, no usable access links, no connected/attached fixture, no stored equipment/objects resting on it, no pitch/roll or unsupported fixture phase. Only capability-enabled camp-chair initially. Start with free idle actor and ground support. Recheck source binding/occupancy/clearance immediately before pickup after gathering, not just plan-time. Stable slot claims prevent competing future sit admission while the fixture moves.

Lift establishes generic held support and the corresponding actor grip before leaving ground. Chair pose and carrier body positions follow one validated continuous trajectory; include rotational corner displacement in motion assertions. Intermediate lift/lower sweeps require the same validated geometry margins, not merely clear endpoint boxes. Recheck humans and ground/static clearance before release. Set-down restores grounded upright pose and original ordinary fixture phase, then grip and claims release only after physical lowering; no construction stored/staged identity leaks.

Cancellation is deferred when holding: finish a validated safe lower, or explicitly refuse when no safe footprint exists and retain coherent actor/hand/entity/slot ownership. A blocked timeout cannot terminally release a suspended chair. First authored proof must have space for cancellation; unsafe cancellation is an honest named retained-load state requiring a subsequent safe instruction, not a fabricated successful end. Escalate if a bounded supported room cannot produce safe cancellation without broad recovery redesign.

## Bounded implementation seam / architecture stop

Prefer a small carry-profile factory with unchanged component default admission/orientation/final phase and a single upright-fixture profile. Share continuous stepping/cancel rather than copy the ~500-line carry executor. Keep construction-specific climb, fragile, staging and assembly logic behind the existing component profile; fixture profile refuses all access links. Factor only ground planning/pose/phase hooks actually required by the chair. Runtime claims and world entity kinds need no new framework.

This does cross carry/action/formation/validation/invariant and minimal renderer boundaries. Root should authorize that explicit ownership set in a new task/worktree. Do not expand this into a universal transport API, arbitrary fixture editor or remodel every carry consumer. Stop if preserving default behavior needs broad construction refactoring or an all-entity physics engine. No existing baseline repinning to accommodate a seam regression.

## Tests and visual proof before release

- Real standalone chair pickup, route and upright target release; seat definition/ID remains intact, ordinary sit succeeds at its new coordinates afterward.
- Missing/wrong capability, actual occupied seat, sit-down/stand-up seat, empty but session-reserved slot, busy/held actor, bowl/spoon hands, unsupported/connected fixture and held surface contents all refuse without world/ownership change.
- Two movers race one chair; sit tries to claim chair during gather and while carried; one winner and named conflicts. Another unrelated chair remains independently usable.
- Corridor fitting actor alone but not chair+carrier refuses; exact target footprint outside floor/overlapping fixture refuses. Human arrives at pickup/target after plan: recheck before support transition/release, preserve held support if blocked. Dynamic carried-chair discs keep unrelated walkers out.
- Cancellation during gather, lift, move, set-down and release; safe targets lower continuously, unsafe current footprint refuses and retains claims/support. No motion jump, dropped/suspended load, stale task/grip or leaked terminal claims.
- End-of-tick recognized-fixture integrity, grip drift, static/human-load clearance and motion bounds hold with existing tolerances. Deterministic repeated seeds/tick inputs. Active snapshot refuses; completed chair snapshot/restore supports sit at final location.
- Existing focused construction carry/meal/social pins pass unchanged. No expected effect on meal, classroom fixed-map or legacy component outcomes; a change there is a compatibility defect to investigate, not a baseline update. Only new chair scenario needs new expected outcome. Generalized carried-load scans may have small branch overhead; root owns later idle performance/full release gate.
- Actual inside-room runtime captures/video at gather, held move/turn, lower and final reseating. Inspect load/body clearance, upright orientation, hand target credibility and continuous pose interpolation. No claim of exact finger contact. Visible room-setup control uses real free worker and an authored empty camp-chair target. Later show occupied/reserved refusal beside running class.

## Table later

Add a table profile only after the chair seam is proven: appropriate larger crew/grips, upright table placement, tabletop contents and surface-slot claims, stability/support and combined formation clearance. Every resting object must be explicitly removed first or handled by separately approved load semantics; never leave bowls floating or implicitly migrate them. Table renderer/contact proof and larger route envelope are separate bounded acceptance. This pass does not authorize them.
